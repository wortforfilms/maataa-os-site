At a glance

What it is

A controller for brushless and DC motors, servos and valve actuators in conveyors, AGVs and small machines. The current loop and encoder reading run at the top priority; the motion profile and the bus run below them as separate tasks.

MAATAA OS

What the OS brings, and what is missing

Today MAATAA OS runs on an STM32F411 (Cortex-M4) board and in QEMU. Drivers today: the USART2 serial port, the status LED and the on-chip flash store. There is no network stack and no over-the-air update. Release 0.1.0-alpha.9.

Works today

Strict-priority scheduler

Pre-emptive, round-robin within a priority level, with priority inheritance on mutexes so a low-priority task holding a lock cannot stall an urgent one.

Here: Priority inheritance keeps a low-priority task that holds the bus lock from delaying the control loop.

Works today

Tasks walled off by the MPU

Each task runs unprivileged in its own memory region. A task that faults is stopped; it is not restarted, and the other tasks keep their memory.

Works today

Signed apps with capability masks

Apps are signed capsules (ed25519). Every system call is checked against the calling task's capability mask, which comes from its signed manifest.

Works today

Mailboxes, mutexes, semaphores

Tasks talk through kernel mailboxes and share hardware through mutexes and semaphores.

Works today

Power-loss-safe store

Settings and logs go to a two-bank flash store, sealed with ChaCha20-Poly1305 under a key bound to the chip. On the F411 board it passed a power-cut test: 9 cuts in 3 runs, no lost or corrupted values.

Here: Tuning values and fault counts stay in the store across resets.

Works today

Watchdog and crash record

The scheduler feeds the hardware watchdog. After a reset the kernel reports the reset cause and a crash record that survived the reset.

Not yet

Work before this concept can run

  • PWM driver for the power stage
  • Encoder and Hall-sensor capture
  • ADC current sensing
  • CAN driver
  • Measured control-loop timing (worst-case timing has not been analysed)
  • The production security profile on a second board
Safety. Not for safety functions. Safe torque off, braking and emergency stop need a separate certified safety controller; MAATAA OS is not certified for safety-critical use.

Guides

For users, makers and partners

Concept briefs. They describe the intended use; none of the steps below is a tested procedure.

User guide

Using it

  1. Screw it to the machine frame through the two M4 ears, near the motor.
  2. Connect the motor phases, the DC supply, the encoder and the CAN bus; keep motor cables away from encoder cables.
  3. Commission it from a laptop over the service port: the host channel reports status and accepts signed setting changes.
  4. Leave it running. It keeps its settings and logs through a power cut.
  5. After any reset it reports why it reset. Send that report to the device maker.

Manufacturer guide

Building it

  1. Pick the hardware from the class list below; the MCU must run MAATAA OS (the F411 today, the production board later).
  2. Bring up the board support: clocks, pins and the service UART.
  3. Add the missing drivers listed under Not yet as walled-off tasks, each with only the capabilities it needs in its signed manifest.
  4. Write the device logic as a signed capsule or a task; keep settings in the power-loss-safe store.
  5. Run the kernel's QEMU checks, then a power-cut test on your board, before any field unit.
  6. Print the enclosure from the files below, then change the parametric source to your real board.

Hardware classes

  • Microcontroller: Cortex-M4F class with motor-control timers
  • Three-phase gate driver and MOSFET bridge sized for the motor
  • Current-sense amplifiers
  • Encoder and Hall inputs
  • CAN transceiver
  • Aluminium lid or heatsink

Classes, not part numbers or prices: these depend on the maker.
