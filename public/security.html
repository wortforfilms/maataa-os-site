Security

What MAATAA OS protects today, and what it does not yet.

This page states the security model plainly, so a reviewer can check it against the code. Every protected item has a test you can run; every gap is on the roadmap.

Protected today

  • Every task in its own MPU region; a task that writes kernel memory or overflows its stack is stopped
  • A guard on the kernel's own stack, and a watchdog with a crash record
  • Apps signed with ed25519; unsigned, wrong-key and older versions refused
  • Each app limited to the system calls its signed manifest grants, with a fuel limit per call
  • Install and remove requests signed over a fresh challenge each boot, so replays fail
  • Store values encrypted and authenticated (ChaCha20-Poly1305), bound to the chip; each key written only by its owner

Not yet

  • Secure boot and a signed kernel image (next milestone)
  • A locked debug port: development boards are open, so store data is not confidential
  • Kernel updates in the field
  • An outside security review
  • Out of scope: timing and power side channels, glitching, a compromised build machine

How we handle keys

Release signing keys stay on the founder's machine and never enter CI or this website. The site's deploy token is limited to its own Worker and zone, and is usable only from the main branch.

This website

No scripts, no cookies, no third-party requests; a strict Content Security Policy, HSTS and framing protection on every page.
