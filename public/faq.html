About MAATAA OS

What is MAATAA OS?

A memory-isolated operating system for microcontrollers, written in Rust. Every task runs in its own memory region, and new features are installed as signed WebAssembly apps without reflashing the kernel.

What hardware does it run on today?

One development board: the NUCLEO-F411RE, with an STM32F411 (Cortex-M4, 100 MHz, 512 KiB flash, 128 KiB RAM). It also runs in QEMU, which is how every push is tested. A second chip family, an STM32H7 or a RISC-V microcontroller, is on the roadmap.

Does it run on phones, PCs or Linux boards?

No. MAATAA OS is for microcontrollers, the small chips that drive motors and read sensors. On a bigger machine it would run on the controller inside it, not on the main computer.

Is it production-ready?

No. It is an alpha. Secure boot, a locked debug port, kernel updates in the field and an outside security review are still ahead. It is not certified for safety-critical use.

Is it open source?

The kernel repository is public at github.com/wortforfilms/os, so anyone can read and test it. It is published under our own licence (LICENSE in the repository), which is being reviewed. Ask us before using it in a product.

Why Rust?

Rust stops whole classes of memory bugs at compile time, without a garbage collector, which suits a kernel that must fit in 128 KiB. The MPU then walls off whatever the compiler cannot check.

Why WebAssembly for apps?

A WebAssembly app cannot reach memory outside its own sandbox, can be checked before it runs, and can be given a fuel limit so it cannot loop forever. That lets a device maker add features after shipping without trusting the new code with the whole machine.

Security

What does "signed app" mean here?

Each app is signed with an ed25519 key. The kernel checks the signature, refuses older versions, and gives the app only the system calls its signed manifest lists. Install and remove requests are themselves signed over a fresh challenge each boot, so a recorded request cannot be replayed.

Is data in the store encrypted?

Not in a way that keeps secrets yet. Every value is sealed with ChaCha20-Poly1305, which detects corruption, but today's builds use a public development key, so anyone can derive the store key. A per-device secret key and a locked debug port come with the production security profile on Rev B. Host reads are unsigned by design.

What happens if power is cut during a write?

The store keeps two banks and seals each record. In our board test we pulled the USB cable nine times mid-write; each time the store came back with the last acknowledged value or the one in flight, never a torn record. Nine cuts is a small sample, not a reliability figure.

Has it had a security audit?

Not yet. An outside review of the kernel, app loader and host channel is a funded milestone. Until then, our threat model lists what is protected and what is not.

How do I report a vulnerability?

Email security@allb.xyz with "security" in the subject, before posting anything in public. See Support.

Business and partners

Who is it for?

Makers of drones, robots and industrial controllers, starting with Indian defence and inspection drones, then industrial and dual-use equipment sold into the EU, where the Cyber Resilience Act makes security updates a legal duty.

How would we pay for it?

A licence per device shipped, a yearly support subscription, and paid porting to your hardware. Our starting ranges are $1–5 per device, $25–50K a year for support and $50–150K per porting project; they will be set with the first design partner.

What is a design partner?

An early customer who tries MAATAA OS on their own hardware, tells us what is missing, and helps shape the first paid pilot. Write to us.

Do you sell hardware?

No. The device pictures on this site are concept renders of where the OS could run. We plan reference designs with partners, who build and sell the hardware.

Is it Indian?

The code is ours, written in India, and the company is ALL B Vegan Private Limited in Delhi. The chip on our board today is an STMicroelectronics part; Indian chips such as SHAKTI or Mindgrove are possible future ports, and our Panini RTL is a path to Indian silicon.

Investors

Are you raising?

Yes: a seed round of ₹10 Cr over 24 months, to fund a team of six, the production security profile, a second chip, an FPGA prototype and the first design partners. Request the deck.

What are the main risks?

Everything so far was built by one person; there are no customers yet; it runs on one board family; and there has been no outside security review. The round is planned around closing those, in that order.

How do you compare with Tock, Zephyr or FreeRTOS?

Tock is our closest peer: a Rust kernel with isolated apps. Zephyr and FreeRTOS are mature C systems; on Zephyr, Ocre and AkiraOS add WebAssembly apps. What MAATAA OS combines is its own Rust kernel and WebAssembly runtime, signed and fuel-limited apps, signed host requests and the Panini engine. The others are far more mature.

Can I see it working?

Yes. Clone the repository and run ./scripts/smoke-alpha.sh for the full QEMU suite, or ask for a live board demo on a call.
