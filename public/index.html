The small controller inside every machine deserves a real operating system.

MAATAA OS is a memory-isolated Rust microkernel for microcontrollers. Every task is walled off by the chip’s memory protection, and new features arrive as signed WebAssembly apps, installed without reflashing.

  • Runs today on an STM32F411 (Cortex-M4)
  • 104,860-byte kernel, 84 KiB of RAM
  • 15 of 15 checks on every push

01 / The problem

Machines now act on their own. Their controllers still run unguarded code.

Drones, robots and industrial machines carry AI computers, but the small controllers that move their motors and read their sensors mostly run C with no walls between tasks. One bug or one bad update can take the whole machine with it. MAATAA OS gives those controllers what larger computers have had for decades: isolation, signed software and a store that survives a pulled cable.

Isolated by default

Every task gets its own memory region from the chip’s MPU. A task that writes where it should not is stopped; the others keep running.

Apps by signature

Features ship as WebAssembly apps signed with ed25519. Each app can make only the system calls its signed manifest grants, and a fuel limit stops it from hanging the system.

Survives power loss

Settings and logs live in an encrypted, authenticated store bound to the chip. A cable pulled mid-write leaves the last value or the new one, never a torn record.

Checkable by anyone

The code is open, and every claim on this site has a script and a log you can run yourself.

02 / How it is built

Four layers, from the chip up.

Each layer below exists in the code today. The tag on the right says how far it has been tested.

04 · Signed apps

WebAssembly capsules, ed25519-signed, each in its own unprivileged task with a fuel limit. Older versions are refused. The Panini grammar engine ships as one of them.

Tested on board
03 · Host channel

A framed link over the board’s USB serial port. Every install or remove request is signed over a fresh challenge from that boot, so a recorded request cannot be replayed.

Tested on board
02 · Services

Message passing, five mutexes with priority inheritance, five semaphores, a watchdog, and a sealed store of 64 keys with an owner for each key.

Tested on board
01 · Kernel

Rust, no_std, no heap. Preemptive scheduler with strict priorities, an MPU region per task, and 19 system calls behind a capability mask.

Tested on board

MAATAA OS has its own kernel and its own WebAssembly runtime, both in Rust; there is no C kernel underneath. Secure boot and a locked debug port are the next layer of work (see Status).
